# Expanded synthetic K=4 campaign (cases 16--29)

This is the human-readable companion to the machine-validated scorecard
`campaigns/k4-expanded14-3466e7a32-h100.json`. The sealed external run root is
`/scratch/gpfs/CRYOEM/gilleslab/em_work/codex/em_k4_expanded14_3466e7a32_20260901`.
The campaign ran RECOVAR commit
`3466e7a32509d6d8b1c6b03dd965375e9c3e103c` and a dispatch-instrumented
RELION executable from commit
`d476e6f6a4f1f37627c06ace5227fc374c0c2b05`. Each paired case ran serially on
one physical NVIDIA H100 80GB HBM3. Slurm requested and allocated exactly one
GPU for every paired case.

## What the campaign covers

The 14 cases vary noise magnitude and model, no-CTF input, contrast and noise
scale heterogeneity, image offsets, 50% outliers, pose concentration, extreme
class imbalance, a 256-pixel high-resolution grid, batch size, rotation block
size, and simulation seed. Every evaluable case compares all five numbered
iterations after independent Hungarian class matching, then records the final
per-class RECOVAR and RELION GT FSC-AUC and their signed difference.

The frozen formal gate is intentionally strict: every matched numbered
class-map cell and the final class maps require direct unmasked FSC-AUC at
least 0.995; every signed RECOVAR-minus-RELION GT FSC-AUC delta must be at
least -0.002; and available per-iteration class-assignment agreement must be
at least 0.99. A formal failure is never rewritten. `SCIENCE_EQUIVALENT`
means the final matched reconstructions retain equivalent per-class GT FSC
quality despite a formal trajectory miss. It is not a claim of bytewise or
trajectory identity.

## Preserved boundaries

- Case 17 is a deliberate zero-class boundary. RELION iteration 1 has hard
  populations `[929, 2023, 0, 48]`. RECOVAR completes its first iteration
  with posterior fractions `[0.2563, 0.2157, 0.2317, 0.2963]`, then refuses
  to normalize the replayed zero-mass class direction prior at iteration 2.
  The endpoint is not evaluable; no artificial class mass is inserted.
- Case 20 is trajectory-exact but near-collapsed: class 3 has only 2/3000
  hard assignments in both engines. It is retained as a boundary, not used as
  ordinary healthy-class evidence.
- Cases 25--27 were intended to probe execution-size invariance. Their poses
  and CTF arrays match, but their independently generated particle stacks have
  different SHA-256 digests despite the common seed (pairwise relative L2
  differences `3.10e-8`--`4.31e-8`). They are therefore
  inadmissible as batch/rotation-block invariance evidence. Case 27 is retained
  as unresolved rather than attributing its separation to rotation blocking.
- Case 18 retains its raw class-4 formal failure (full-shell direct FSC-AUC
  0.991837). A sealed follow-up found no rigid drift: zero integer and phase
  shift, and a fitted 0.03745-degree/0.00654-voxel motion makes FSC slightly
  worse. The live-shell 1--19 FSC-AUC is 0.995923, a tight engine-symmetric
  mask gives 0.999593, and the GT delta is +0.000294. The late fork consists
  of 13 class, 76 rotation, and 49 translation winner mismatches among 3000
  particles. The frozen formal result remains `FAIL`; the diagnosis is sealed
  at `/scratch/gpfs/CRYOEM/gilleslab/em_work/codex/k4_case18_fsc_diagnosis_20260901/diagnosis.json`.

## Reproduce

The exact generated-data parameters and complete RECOVAR/RELION commands are
inside each hashed case launcher and `case_config.json`. To reproduce the
campaign, first build the isolated environment and shared bindings:

```bash
sbatch /scratch/gpfs/CRYOEM/gilleslab/em_work/codex/em_k4_expanded14_3466e7a32_20260901/jobs/em_kclass_matrix_setup.sh
```

After that setup job succeeds, submit any case launcher, for example case 16:

```bash
sbatch /scratch/gpfs/CRYOEM/gilleslab/em_work/codex/em_k4_expanded14_3466e7a32_20260901/jobs/em_kclass_matrix_16_ribo_k4_3k_g128_white_noise10_uniform.sh
```

After all case jobs reach a terminal state, regenerate the compact endpoint
summary and numbered-trajectory audit:

```bash
sbatch /scratch/gpfs/CRYOEM/gilleslab/em_work/codex/em_k4_expanded14_3466e7a32_20260901/jobs/em_kclass_matrix_summary.sh
sbatch /scratch/gpfs/CRYOEM/gilleslab/em_work/codex/em_k4_expanded14_3466e7a32_20260901/jobs/audit_numbered_trajectories.sbatch
```

The scorecard records the exact launcher/config/input hashes, jobs and
accounting, per-class signed metrics, occupancies, wall times, HBM peaks,
artifacts, and limitations for each case. Validate the checked-in record with:

```bash
pixi run python scripts/validate_em_benchmark_registry.py
pixi run pytest tests/unit/test_validate_em_benchmark_registry.py
```

Use `--verify-files` on the validator to rehash every external file referenced
by the scorecard. Missing files, size changes, and digest changes fail closed.

## Limitations

All cases use one Ribosembly molecular family, C1 symmetry, 3000 particles,
and a five-iteration cap. RECOVAR did not converge before the cap and did not
run final-all-data reconstruction, so the maps are last-numbered iteration
products. The campaign is strong K=4 parity and boundary evidence, but it does
not replace converged, high-particle, symmetric, or real-data K=4 validation.
